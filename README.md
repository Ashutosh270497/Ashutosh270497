## 🧭 How I Think About Production Systems

<table>
<tr>
<td width="50%" valign="top">

### 🧱 Bounded Autonomy
Every automated workflow needs step limits, timeouts, retry ceilings, cost controls, and deterministic exit conditions.

### 🔐 Safe Tool Execution
Mutating operations need authorization, idempotency, preconditions, approval boundaries, and an explicit retry contract.

### 👁️ Observable by Default
Requests, plans, tool inputs, policy decisions, outcomes, and failures should be traceable end to end.

</td>
<td width="50%" valign="top">

### 🧯 Failure as a Design Input
Timeouts, partial success, stale state, unavailable dependencies, and rollback paths should be designed before launch.

### 🧑‍✈️ Human Control at the Right Boundary
High-impact actions such as deploying, deleting, spending, or notifying customers should require explicit approval.

### 🔄 Recovery Over Optimism
A system is not production-ready until it can detect, contain, explain, and recover from failure.

</td>
</tr>
</table>
